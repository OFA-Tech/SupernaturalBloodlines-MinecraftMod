## Slot helper and Curios (Task 1)

- `ArtifactSlots` (`parts/artifacts`) is the only entry point. `InventorySlots` (package-private) walks `inventory.items` (hotbar included), `armor`, `offhand`. `curios/CuriosSlots` is the only class that imports Curios; `ArtifactSlots` calls it only behind `ModList.get().isLoaded("curios")`, so with `-PnoCurios` no Curios class is ever loaded (the inventory test would throw `NoClassDefFoundError` otherwise).
- `findWorn` returns the stack itself (not a copy), Curios first, so callers can read and edit data components (bound UUID, charges).
- **Curios 9.5.1+1.21.1** (`top.theillusivec4.curios:curios-neoforge`, repo `maven.theillusivec4.top`; `api` classifier for compile, full jar for `localRuntime`; range `[9.5,10)` in `neoforge.mods.toml`, optional). API packages: `top.theillusivec4.curios.api` (`CuriosApi`, `CuriosCapability`, `SlotContext`, `SlotResult`, `SlotTypePreset`, `CuriosTags`), `.api.type.capability` (`ICuriosItemHandler`, `ICurio`, `ICurioItem`), `.api.type.inventory` (`ICurioStacksHandler`, `IDynamicStackHandler`), `.api.event` (`CurioChangeEvent`, `CurioCanEquipEvent`, `CurioCanUnequipEvent`, `DropRulesEvent`, ...), `.api.client` (`ICurioRenderer`).
- **Registering a ring needs no code in 9.x.** `CuriosApi.registerCurio(Item, ICurioItem)` exists but is only for custom equip behaviour. A ring is equippable when the item is in the item tag `curios:ring` (`data/curios/tags/item/ring.json`, entries `required: false`); the `ring` slot's validator is `curios:tag`. Task 2 adds that tag with the ring items.
- **The player has no Curios inventory until a data file gives it slots.** Curios ships slot types only, no entity assignment. We ship `data/supernaturalbloodlines/curios/entities/player.json` (`entities: ["player"]`, `slots: ["ring"]`). Curios ignores `neoforge:conditions` in that folder (verified: with `-PpartsOff=artifacts` it still logs "Loaded 1 curio entities"), so an empty ring slot also shows with the part off. Harmless.
- **The OFA pack runs Accessories**, which ships a Curios compatibility layer: Curios API calls are expected to go through to Accessories slots (not verified here). `-PnoCurios` only proves the no-Curios path; the Accessories-with-compat path needs a manual check in the pack (Task 8).
- Gotchas found by the tests:
  - `CurioInventory` caches `findFirstCurio` per player for the current game tick (`firstCurioCache`). A lookup made before an equip in the same tick returns the stale "none". Irrelevant in play (equip and check are on different ticks), but a GameTest must not query the same player before equipping.
  - `Inventory.contains(Predicate)` is patched by Curios and also looks into curio slots. To ask "is it in the vanilla inventory", walk `items`, `armor` and `offhand` (as `InventorySlots` does).
  - Tests put a stack straight into `getStacksHandler("ring").getStacks()`, because the stand-in item is not in `#curios:ring`.

## Hook points (verified against the 1.21.1 jars)

Vampirism 1.10.13:

- **Sun damage.** Damage type `vampirism:sun_damage` (`ModDamageTypes.SUN_DAMAGE`, full jar; `message_id` `sun`). **No sun event and no per-player skip hook.** The related events are only `VampireFogEvent` and the registry `ISundamageRegistry` (`isGettingSundamage(LivingEntity, LevelAccessor)`, biome/dimension settings, `data/<ns>/vampirism/no_sun_damage.json`; per biome and dimension, not per player). For players it runs in `VampirePlayer.onUpdate -> isGettingSundamage(level, true) -> handleSunDamage(boolean)` (private): it counts `ticksInSun` (cap 100), reads the `vampirism:sunscreen` effect (`ModEffects.SUNSCREEN`, amplifier 0..4), and past 50 ticks deals damage; at 100 ticks it can kill outright (`vpSundamageInstantDeath`, `DamageHandler.kill`, then `turnToAsh`); it also adds Nausea and Weakness above configured levels. `isGettingSundamage` is false while the main hand holds the Umbrella.
  - Options for the Sun Ring (Task 3): (a) cancel `LivingIncomingDamageEvent` when `source.is(SUN_DAMAGE)` and the victim wears its bound ring (the damage type key can be built without linking the class: `ResourceKey.create(Registries.DAMAGE_TYPE, ResourceLocation.parse("vampirism:sun_damage"))`; see `vampirism_enchanted.md`); that stops the damage but not Nausea/Weakness/instant death, which are applied without a damage event; (b) additionally keep a short `vampirism:sunscreen` effect on the wearer, since `handleSunDamage` reads it. Task 3 decides, with a GameTest.
- **No glowing / compulsion API.** There is no compulsion class or event. `GlowingEyeCommand` / `EyeCommand` only set eye rendering. `IVampireVision` (`NightVision`, `BloodVision`) is the nearest "see through" feature and is client side. Vervain's compulsion immunity is therefore ours: a rule (`VervainRules.protects`) that plan 8's compulsion checks (core `CompulsionImmunity` registry).
- **Bite.** Victims implement `IBiteableEntity` (`canBeBitten(IVampire)`, `onBite(IVampire)`); the vampire side is `VampirePlayer.biteEntity(int)` / `determineBiteType` (`IVampirePlayer.BITE_TYPE`). Neither fires an event. The only event on a bite is `BloodDrinkEvent` (`PlayerDrinkBloodEvent` / `EntityDrinkBloodEvent`; not cancellable, but `setAmount` and `setSaturationModifier` work; `getBloodSource().getEntity()` should be the victim; not yet exercised). That is the hook for "vampires burn when they bite a vervain wearer": listen for `BloodDrinkEvent.PlayerDrinkBloodEvent`, check the victim with `VervainRules.protects`, hurt `getVampire()`'s player entity and set the amount to 0. A hit barehanded is plain `LivingIncomingDamageEvent` / `LivingDamageEvent.Post` on the victim with an empty-hand attacker.
- **Vampire eating.** Vampirism's own handler is `ModPlayerEventHandler.onItemUse(LivingEntityUseItemEvent.Finish)`: for a vampire finishing a `GarlicBreadItem` it calls `DamageHandler.affectVampireGarlicDirect(IVampire, EnumStrength.MEDIUM)` (`de.teamlapen.vampirism.util`, full jar). That is the precedent for "vampires who eat vervain take damage": our own `LivingEntityUseItemEvent.Finish` listener, `Helper.isVampire`-style faction check via `VampirismAPI.factionPlayerHandler(p)`, then hurt the player (or call `affectVampireGarlicDirect` if linking the full jar is acceptable). `onItemUse(Start)` only cancels use for faction-restricted items (`IFactionExclusiveItem`, `IFactionLevelItem`) and the "cannot interact" state.
- **Forced full-moon shift (Werewolves 2.0.3.4).** `WerewolfPlayer.onUpdate()` once a second toggles a form action through `ActionHandler.toggleAction`, which fires the cancellable `ActionEvent.ActionActivatedEvent`. A voluntary shift comes from a packet outside the player tick. Already implemented for hybrids in `parts/species/hybrid/FormControl` (thread-local "inside this player's `PlayerTickEvent`" flag; no mixin); notes in `docs/parts/species.md`. The Moon Ring (Task 2) reuses that detection through `shared.werewolves.MoonControl` (see the plan 6 ledger).

Enchanted 4.2.7:

- **Kettle recipe JSON**, `data/<ns>/recipe/<name>.json`, type `enchanted:kettle`:
  ```json
  {
    "type": "enchanted:kettle",
    "cook_colour": "801E17",
    "final_colour": "DE311D",
    "ingredients": [ { "id": "minecraft:redstone", "count": 1 }, { "id": "enchanted:mandrake_root", "count": 1 } ],
    "power": 1000,
    "requires_bottle": true,
    "result": { "id": "enchanted:redstone_soup", "count": 1 }
  }
  ```
  `power` (altar power, optional, absent = none) and `requires_bottle` (optional, default false) are optional; colours are hex without `#`. Ingredients are `{id, count}` (all seen examples name items; tags not checked). Vanilla examples: `data/enchanted/recipe/kettle/*.json` in the Enchanted jar. Wrap with `neoforge:conditions` (`part_enabled` artifacts).

## Sun Ring and Moon Ring (Task 2)

- **Items** (`ArtifactItems`): `sun_ring`, and `moon_ring` only when Werewolves is loaded (the field is null otherwise). Both are `BoundRingItem` (stack size 1; tooltip "Bound to <name>", the name from the client tab list, else the UUID; "Not bound to anyone" when unbound). Data component `supernaturalbloodlines:bound_to` (UUID, synced). An unbound ring does nothing. `ArtifactItems.isBoundWorn(player, item)` asks for a worn copy bound to that player; `ArtifactSlots.findWorn(p, item, filter)` takes a filter so a foreign ring cannot hide the wearer's own.
- **Sun protection** (`SunRing`): Vampirism has no sun event, so `LivingIncomingDamageEvent` of `vampirism:sun_damage` is cancelled for a bound wearer (the damage type is looked up by id, no Vampirism class beyond the API). **Sun debuffs are separate** (read from `VampirePlayer.handleSunDamage`): the kill after 100 ticks (`vpSundamageInstantDeath`) and Nausea happen without a damage event; both read the `vampirism:sunscreen` effect, which caps the sun counter at 50 for amplifier 0 to 3 when `vpSunscreenBuff` is on (default). So the bound vampire keeps a hidden 40 tick sunscreen effect (refreshed every 20 ticks, only for vampires). **Not stopped:** Weakness (152 ticks every 150 ticks in the sun, only blocked by amplifier 5+, which would lift the cap). If `vpSunscreenBuff` is off in the Vampirism config, only the damage is stopped.
- **Moon control** (`shared.werewolves`): `MoonControl.of(ServerPlayer)` is NONE, HALF or FULL. Sources are predicates registered with `MoonControl.addSource` (artifacts: a bound Moon Ring is worn; species: hybrid types; plan 9 adds Alphas and anchors). With a source, HALF; FULL from Werewolves level `werewolves.full_form_level` (common config, default 8). The Werewolves faction is matched by id, so `MoonControl` links no Werewolves class. `ForcedShift` (links Werewolves; register only behind `isLoaded("werewolves")`, idempotent) holds the thread-local "inside this player's tick" flag and cancels a forced `WerewolfFormAction` when `MoonControl.of(p) != NONE`. Nothing is blocked without control: plan 9 enforces that. Voluntary shifts are untouched.
- **Bind rite** (`rite/BindItemRiteFactory`, `supernaturalbloodlines:bind_item`): fields `input`, `output`, optional `faction` (`vampire`, `werewolf`, ... as in `faction_rite`). The input is looked up among the rite's consumed items (Enchanted consumes the JSON `items`); the target is `RiteTargets.centrePlayerOrCaster`. Refused with a message and a refund (Enchanted gives the consumed items back on `cancel()`): no input among the consumed items, input already bound, target in the wrong faction. No target at all just cancels (nobody to tell). The output is a fresh stack with `bound_to`, dropped above the circle.
- **Recipes and rites:**
  - Sun Ring: shaped, gold ingots at the four sides, glowstone in the middle. Moon Ring (Werewolves): the same with silver ingots and an amethyst shard.
  - *Ward of Daylight*: sun ring, 2 sunflowers, 4 glowstone dust; medium circle; 6000 power; target a vampire (faction VAMPIRE).
  - *Ward of the Moon*: moon ring, 2 amethyst shards, 2 silver ingots; medium circle; 6000 power; target a werewolf (faction WEREWOLF, which hybrids are in).
- **Curios:** `data/curios/tags/item/ring.json` lists both rings with `required: false` (tags cannot take conditions; an absent moon ring is just skipped).
- No mixin was added.

## Resurrection Ring and Vervain (Task 3)

- **`core/Supernatural`**: predicate registry on plain Minecraft types, `register(isSupernatural, isVampiric, isPrey)` any number of times (OR-combined), `is` / `isVampiric` / `isPrey`. Artifacts registers (`VampirismSupernatural`, factions by id, no Werewolves class): vampire and werewolf players and mobs; hunters are not supernatural. Species registers (`SpeciesSupernatural`): supernatural = every species except NONE, POTENTIAL, HUNTER_OF_THE_FIVE; vampiric and prey = ORIGINAL, ORIGINAL_HYBRID, HYBRID, TRIBRID, HERETIC (witches and siphoners are never prey, R81).
- **Resurrection Ring** (`ResurrectionRing`, item `resurrection_ring`, component `charges`, default 3): `LivingDeathEvent` at **NORMAL**, not receiving cancelled events. Vampirism is HIGHEST and OriginalRules HIGH (a death they saved costs no charge); TransitionHandler and GeneAwakening are LOW (a revived victim must not count as a kill). Victim: a player, species NONE/POTENTIAL/HUNTER_OF_THE_FIVE, not a vampire or werewolf; attacker `Supernatural.is`. The ring is looked up again at use time (`ArtifactSlots.findWorn` with a charges > 0 filter), so one that left the inventory mid-death does nothing. Effect: cancel, full health, Regeneration II for 10 s, charges - 1 (an empty ring stays, at 0). Rite *Ward of Return* (`ward_of_return.json`, medium circle, 8000 power: totem of undying, 4 gold ingots, diamond, `enchanted:create_item`). Pinned by `resurrectionRingRunsBetweenSaversAndConsequences` and `ResurrectionRingRulesTest`.
- **Vervain**: block `vervain` (CropBlock, 8 ages, 4 placeholder stage textures), `vervain_seeds`, `vervain` (edible, 1 nutrition), `vervain_tea` (drink, gives the `vervain` effect for 12000 ticks, returns a glass bottle). Kettle recipe `recipe/kettle/vervain_tea.json` (2 vervain + sugar, needs a bottle). Seeds: block loot (seeds always, herb at age 7) and `loot_table/chests/vervain_seeds` (25% for 1 to 3) added by a NeoForge global loot modifier (`neoforge:add_table`, `data/neoforge/loot_modifiers/global_loot_modifiers.json`) to the five village house chests, gated by `part_enabled artifacts`. Not done: growing near white oak.
- **`VervainRules.protects(Player)`**: the effect, or vervain in the offhand (main hand and inventory do not count). Used by plan 8 for compulsion.
- **Burn** (4 magic damage + Weakness I 10 s to the attacker): (a) `BloodDrinkEvent` (abstract, so a listener on each of `PlayerDrinkBloodEvent` and `EntityDrinkBloodEvent`): the victim from `getBloodSource().getEntity()`, the biter is `getVampire().getRepresentingEntity()`, and the amount is set to 0; (b) `LivingDamageEvent.Post` on a protected player from a melee hit (`player_attack`, `mob_attack`, `mob_attack_no_aggro`, direct = attacker) with an empty main hand by a `Supernatural.isVampiric` attacker. Hybrids bite through Werewolves, which fires no event, so only their barehanded hits burn. A vampiric player who finishes eating vervain or the tea takes 6 (`LivingEntityUseItemEvent.Finish`). Vampirism trims magic damage a little (1.4% on a level 1 player; a mob test run lost only 2.4 of 4), so the tests spy on LivingIncomingDamageEvent (HIGHEST) and assert the pre-reduction amounts, 4.0 for the burn and 6.0 for eating.
- **Sun Ring fold-in:** `refreshSunscreen` skips a vampire who already has a real `vampirism:sunscreen` (visible, or amplifier > 0). Test `sunRingLeavesARealSunscreenAlone`.
- **Debt (vervain):** (1) a werewolf's bite does not burn: Werewolves fires no event for it, so there is nothing to hook (hybrids still burn on a barehanded hit). (2) A vervain bite sets the drained blood to 0 (`setAmount(0)` and no saturation). That is a deliberate decision, not a leftover: the biter is punished and gets nothing for it.

## White Oak Ash Dagger and The Cure (Task 4)

- **Items** (`ArtifactItems`): `white_oak_ash`, `white_oak_ash_dagger` (`AshDaggerItem`, stack 1, 2 attack damage, slow), `the_cure` (`TheCureItem`, a drink that returns a glass bottle, epic, glint). Effect `desiccated`, attachment `supernaturalbloodlines:lodged_dagger` (an ItemStack, saved with the player, **not** `copyOnDeath`).
- **Recipes** (both conditioned on `part_enabled artifacts` and `species`, because the ash comes from species' white oak log, named by id): smelting `supernaturalbloodlines:white_oak_log` -> `white_oak_ash` (200 ticks); the dagger is shaped, ash over iron ingot over stick. With species off neither exists and Originals cannot exist either: accepted.
- **The hit** (`AshDagger`, `LivingDamageEvent.Post` at LOWEST, melee only, wielder = direct = causing entity, dagger in the main hand): a victim player whose species is ORIGINAL or ORIGINAL_HYBRID (core `BloodlineAccess`, no species classes) and who is not already desiccated gets `desiccated` for 36000 ticks and the dagger (one item, taken out of the wielder's hand unless creative) goes to `lodged_dagger`. A second dagger is left with its wielder.
- **`desiccated`**: Movement speed and jump strength -100% (attribute modifiers of the effect; they survive a relog, tested). Attack, every right/left click, entity interaction, block break and item use start are cancelled at HIGHEST for anyone with the effect. **Not done: the grey screen tint** (only the grey icon/swatch).
- **Ending it** drops the dagger exactly once at the player's feet (`release` is idempotent): another player's right click (`PlayerInteractEvent.EntityInteract`, handled and cancelled; a desiccated player cannot pull their own), `MobEffectEvent.Expired` (the timeout), `MobEffectEvent.Remove` (milk, a command), or a real death (`LivingDeathEvent` at LOWEST, not receiving cancelled ones, so the Original's downed state keeps its dagger).
- **Wielder rule:** `Supernatural.is(wielder)` -> 10 magic damage on every melee hit with the dagger (the hit lands first). The source has the wielder as its **direct** entity and no causing entity on purpose: `ServerPlayer.hurt` refuses a source whose causing entity is a player when `canHarmPlayer` says no (PvP off), which would let a player wield it for free.
- **Rite of the Cure** (`rite_of_the_cure.json`, factory `supernaturalbloodlines:requires_desiccated`, medium circle, 20000 power, 2 white oak ash + 4 vervain + enchanted golden apple, conditioned on `part_enabled artifacts`): needs a living player with `desiccated` and species ORIGINAL/ORIGINAL_HYBRID within 6 blocks of the circle centre; then drops The Cure above the circle. Otherwise the caster gets `rite.needs_desiccated` and Enchanted refunds everything. The `entities` field is not used (it takes entity types to sacrifice, not "a player nearby"). Checked by core `partDataFollowsSwitch`.
- **Drinking The Cure:** `BloodlineAccess.applyEvent(p, DRANK_THE_CURE, FactionRiteHooks.context(...))`, then `FactionRiteHooks.run` (species' `OutcomeExecutor` when species is on, `FactionRiteFactory.runFactionActions` otherwise). That runner is the only place `leaveFaction(false)` is called. Artifacts imports no species class. Tested with species on and with `-PpartsOff=species`. A human loses the potion and nothing else happens. **The desiccated Original cannot drink it** (item use is blocked): someone pulls the dagger first, or another vampire drinks it.
- Placeholder textures are generated (ash, dagger, bottle, effect icon).
- **Review fixes:** the dagger is only taken from the wielder once `addEffect` succeeded. Clicking a desiccated player while holding The Cure (either hand) cures them (`TheCureItem.cure`), gives the feeder a glass bottle and frees them; it wins over a pull. Dropped daggers have a 20 tick pickup delay and `/effect clear` releases the dagger. **Known gap:** a desiccated vampire can still start a Vampirism bite (a packet, only the uncancellable `BloodDrinkEvent` follows).
