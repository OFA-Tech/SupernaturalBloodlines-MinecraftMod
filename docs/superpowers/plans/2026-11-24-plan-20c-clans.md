# Plan 20c: Clans (Day Walkers, shared feeding, the sire-line bonus, the Charter and the Game of Kings, exile): Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the clan type of plan 20a its perks. A clan is led by a vampire-like leader (vampire, Original, Augustine, vampire-siphoner). New members are **Night Walkers**; the leader promotes a member to **Day Walker**, or a Night Walker is promoted after 14 real days in the clan. A feed near clanmates gives each of them a little blood (**shared feeding**), and clanmates of one sireline who stand near each other hit harder (**sire-line bonus**). A clan with 3 or more members can forge its **Charter**; a Day Walker with 7 days in the clan can **challenge** for it (**Game of Kings**): the leader must accept, a clan has at most one contest per 7 days, and at the next in-game midnight the **online Day Walker or leader holding the Charter leads**. A leader may **exile** a member (no shunning vote, no Garden). The coven-forged half-power Sun Ring of 20b now defaults to Day Walkers only (`sun_ring_day_walker_only` true). No new Part, no new mixin; one new item (the Charter, not craftable, in no tab).

**Architecture:** Pure rules in `core.group.clan` (rank timing, shared-feed shares and caps, the sire-line count, the Charter state machine, the contest table, midnight detection, exile arithmetic). Rows live in the existing `GroupIndex` (`charters` and `contests` are new; exile uses `bans`, contest and reforge timers use `cooldowns`, ranks use `ranks`: all from 20a/20b, so a 20b jar keeps the new rows as unknown keys). The lead moves through `GroupLead.handOver` (the one path the absence rule and the coven election already share). Shared feeding listens to Vampirism's `PlayerDrinkBloodEvent` at `LOWEST` behind a `shared.supernatural.SharedFeed` guard that the other feed listeners read. The Charter is one item (`supernaturalbloodlines:clan_charter`) registered by the species part; the server row is the truth, the stack is a token. One new S2C payload (`ClanViewPayload`) carries the viewer's own clan card; one request kind (`CHARTER_CONTEST`) rides the existing requests channel; every action is a typed command with a hub button and an `AdminCommands` row.

**Tech Stack:** Java 21, NeoForge 21.1.265 (MC 1.21.1), Vampirism 1.10.13, Werewolves 2.0.3.4 (compile only, optional at run time), Enchanted 4.2.7 (through the 20b ring rite), JUnit 5, the repo's GameTest runner.

**Spec:** [docs/superpowers/specs/2026-11-23-groups-design.md](../specs/2026-11-23-groups-design.md) (sections 7, 8, 9, 10, 11, 13, 16; this plan corrects it where the code says otherwise, see "Spec corrections"). Base plans: [20a](2026-11-23-plan-20a-groups-base.md) and [20b](2026-11-24-plan-20b-covens.md), both merged (main `9981e17d`). Lore: [research/groups-lore.md](../research/groups-lore.md) section 2 and 6.2.

Repo conventions that apply: one branch `feature/plan-20c-clans`, one PR, a `CHANGELOG.md` entry with a "Rolling back" paragraph, `docs/parts/species.md` ticked, the rules copied into `docs/superpowers/specs/SPECIES-RULES.md` as **R270 to R281** (R282 to R289 reserved), no narrating code comments, hidden hub shots per `docs/safe-screenshots.md`.

## Global Constraints

- **No new Part, no new mixin.** Everything is inside `species` (the item, the listeners, the commands) plus two one-line guards in listeners that already exist (`AugustineRules`, and whatever Task 0 finds in `parts/artifacts`). Species is at its mixin limit: if a task seems to need one, stop and use an event or a public API instead (the pickup denial, the invulnerable entity and the feed guard below are all events and flags).
- **Rule ids R270 to R281** (R282 to R289 reserved; 20d keeps R290-R299, plan 21 R300-R329). Allocation: R270 ranks (Night Walker, Day Walker, promote, demote, the 14 days), R271 the Charter (the item, forging, the states), R272 the challenge (who may, accept, the 7-day limit), R273 the Sun Ring for Day Walkers, R274 shared feeding, R275 the sire-line bonus, R276 exile, R277 the midnight (who leads), R278 lost and reforged, R279 protection (non-griefable), R280 dormancy (a type switch, clans off, Charter off), R281 privacy (nothing about other clans, no species, no sireline root).
- **Config:** the existing `supernaturalbloodlines-groups.toml`, section `groups`, **18 new keys** (Task 1; the spec's 16 minus `sun_ring_discount_percent`, which 20b made the rite file's own `power`, plus `challenger_min_days`, `contest_min_minutes`, `charter_forge_cost`). `AdminEntries.ALL.size()` is **259 on main today** (read from `AdminEntriesTest`), so **259 + 18 = 277** (`AdminSnapshotPayload.MAX_ROWS` is 320: 43 rows are left, 20d needs 16). Every key has an Admin row (the existing `AdminAccess` gate, permission 2, is the only gate: no new Admin action), an `en_us` key, and the section title already exists. `sun_ring_day_walker_only` keeps its key and gets its default flipped to `true`.
- **Wire:** one new S2C `ClanViewPayload` on the optional registrar of `LadderNet`; `HubRequests.Kind` gets `CHARTER_CONTEST` appended after `GROUP_VOTE` (sent by name, so an old client fails on the unknown name: that is why the bump is required); `LadderNet.PROTOCOL` becomes **the integer after the one on `main` at merge time** (`"17"` today, so `"18"`), and `SnapshotIdsWireTest.GOLDEN_PROTOCOL` follows in the same commit (`GOLDEN_HEX` does not change). No new C2S payload: buttons run typed commands.
- **UI-first:** every new literal of the `/group` tree has a hub control (`GroupButtons.IDS`, `GroupUiCoverageTest`) **and** an `AdminCommands` row with root `group` and `Ui.HUB_BUTTON` (`C11` to `C17`, so 72 + 7 = 79 rows). The clan's challenge and accept rows are **their own** `group` rows, not `P8` to `P10`: `HubCommands` rewrites a `pack` row to `/group` only when `/pack` is not registered, so with Werewolves loaded a shared row would run the pack duel for a clan leader. A command the player can only type is a bug.
- **Privacy (R281):** the clan view and every refusal say nothing about people outside the viewer's clan, never a species, a sireline root, another clan's Charter, or whether someone is an Original. A hidden Original who leads or joins a clan is a name like any other. The Sun Ring refusal is the one generic `NOT_FOR_YOU` line whatever the reason (wrong faction, no clan, Night Walker).
- **Part isolation:** `artifacts` requires only `vampirismEnchanted`, so `VervainRules` and `AshDagger` (both read `PlayerDrinkBloodEvent`) cannot import a species class. The feed guard is `shared.supernatural.SharedFeed` (a static `ThreadLocal`, default "not a share"), the same seam pattern as `HubGroups`, `HubCoven` and `CircleQuery`; the clan view uses a `shared.supernatural.HubClan` seam the species part installs.
- **Tests:** GameTests never loop on `entity.tick()` waiting for `tickCount` (pin time with `PackIndex.overrideClock` and drive the code under test directly); fake test players cannot mount vehicles (nothing here needs one); use `TestPlayers.createMortal` for any test where a death must be announced; heavy Gradle runs go through `C:\Users\caiom\AppData\Local\Temp\opencode\gt-slot.ps1` with `--max-workers=2`; restore `run/config` after any killed run; hidden screenshots need a **copied world** and must wait while the owner's own Minecraft window is open (`docs/safe-screenshots.md`).
- **Shapes of the existing code to keep:** `PackIndex` and `HubSnapshotPayload` are not edited; `GroupIndex` only gains two rows (its `KNOWN` set grows, so a 20b jar keeps them as extras); `GroupButtons.IDS` is already a `Map.ofEntries` (20 entries); `GroupLead.handOver` is the only way a lead moves; `GroupSwitcher.onSwitched` is the only hook for "the type changed".

## Spec corrections (made in this PR, in the spec and in the 20a outline)

1. **Rule numbers (7.6 and 7.1 to 7.5):** the spec gave R270 to R272 to the contest and R277 to R279 to the Charter; this plan allocates R270 to R281 as listed in Global Constraints (ranks and the Charter get their own ids). Numbers only; the rules are the spec's.
2. **Config (section 9, 20c row):** 18 keys, not 16: `sun_ring_discount_percent` goes (20b made the discount the rite file's own `power` 3000, a datapack value); `challenger_min_days` (7: the spec had it as a bare number in Q5), `contest_min_minutes` (2) and `charter_forge_cost` (a `LIST`, the spec's "config item list") are added.
3. **7.2 (the Vampirism hook):** `VampirismAPI.vampirePlayer(mate)` is never empty; the mate test is `VampirismSupernatural.isVampire`. "Refuse any event whose source is empty" is not enough: `AugustineRules` does not refuse one, so the share goes through the `SharedFeed` guard that every listener reads.
4. **7.4 and 8 (Sun Ring):** 20c flips `sun_ring_day_walker_only` to `true` (owner answer 1 of plan 20b). A clan **leader** counts as a Day Walker for the ring (owner answer 1). The rank is read when the ring is **forged**, never afterwards: a demoted or exiled holder keeps the ring.
5. **10.2 (command table):** `challenge` for a clan is `group challenge` (the Day Walker) and `group challenge accept` (the leader), rows `C11` and `C12` with root `group`. A clan leader cannot decline (the lore says must accept), so `challenge decline` answers `no_decline` on a clan and has no button there.
6. **7.1:** `demote` exists (10.2 had the button, 7.1 only the verb) and a demoted member is **not** auto-promoted again (the leader promotes them again). The 14 days are real days in the clan (`PackIndex.inPackSince`).
7. **7.6 (resolve):** the contest resolves at the first midnight at least `contest_min_minutes` (2) after it started, so a leader who accepts one second before midnight does not hand the Charter to whoever happens to hold it. The scan is run again right before the read (the holder at midnight is the holder **now**, not 40 ticks ago).
8. **7.6 (stripped Charter):** a Charter found with a non-member is taken out of their inventory and dropped at their feet, protected (only clan members can pick it up). Nothing is destroyed.
9. **11 (wire):** the payload is `ClanViewPayload`, the request kind `CHARTER_CONTEST`, `AdminEntries` 277, `AdminCommands` 79, `PROTOCOL` "18".
