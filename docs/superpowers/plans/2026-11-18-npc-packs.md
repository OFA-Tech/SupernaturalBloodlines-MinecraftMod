# Plan 15: NPC packs and Howling ideas

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The world carries the werewolf lore. Full moons bring NPC werewolf packs that hunt in a fixed order (vampire, hunter, player, prey); their Alphas drop a weaker spark that grows inside the holder; a player can win a new spark in the Alpha Trial, recruit NPC wolves as pack members (the Werewolf Brother rite, plus Tensura subordinates), and read the moon from a calendar in the hub. The Howling Werewolf ideas are reimplemented in our own code (no compat, no Howling jar, no Howling art).

**Branch:** `feature/npc-packs` (this plan only). Each phase below is its own branch and PR, built in order. **15a** has no dependency. **15b to 15d need PR #39 (`feature/spark-rules`) merged first**: they use `WolfState.heldSpark`/`protectPath`, `PackRules.stealBy`/`effectiveSparks`/`pathOpen`, `AlphaTrial.win(beta, warned)`, `TrueAlphaWarning.applies` and `HubScreen.warnTrueAlpha(Runnable)` (read from `origin/feature/spark-rules`, commit `16c0119`). Rebase on `main` after the merge and re-read those files before starting 15b.

**Sources:** `specs/2026-11-16-bloodlines-bosses-design.md` section 6 and the "Weaker NPC spark" paragraph; `specs/2026-11-17-hub-information-architecture.md` (rows for plan 15, section 3.6 NPC profiles, 3.7 knowledge table); `specs/SPECIES-RULES.md` R90 to R94c plus R91c/R93b/R93c from PR #39; `specs/2026-11-17-enhanced-celestials-compat.md` (Blood Moon row, `blood_moon_pack_chance_factor`); the Howling Werewolf 1.3.8 public description and CONFIG/PROGRESSION docs (web, read 2026-11-18, for the ideas only).

## Decisions made while planning (reversible; each is cheap to flip)

1. **No new part, no new mixin.** The code goes in the `species` part (`parts/species/npc/`, `parts/species/moon/`), the Tensura bridge in `species_tensura`, the calendar in `supernatural`. `species` is already at **3 of 3 mixins** (`docs/mixins.md`), so everything here uses NeoForge events, all checked to exist (table below). A new part was rejected: it would need `requiredParts = SPECIES` (a second documented exception to "parts never import each other"), a new CI run and a new Admin section, for no gain. Every feature still has its own config switch, and `-PpartsOff=species` turns all of it off.
2. **Werewolves classes stay behind `ModList.isLoaded("werewolves")`**, like `SpeciesPart` does today. The `-PnoWerewolves -PnoCurios` run proves it (no class load, no spawner, no rite).
3. **Art needs nothing new.** We spawn the Werewolves mod's own entity types, so their renderers and 126 skins apply: `werewolves:werewolf_beast`, `werewolves:werewolf_survivalist`, `werewolves:human_werewolf`, `werewolves:alpha_werewolf`, and `werewolves:wolf` (`AggressiveWolfEntity`, a `Wolf` with `restrictLiveSpan(int)`) for the Wolf Spirits. The `art-*` branches stay for plan 17.
4. **No AI goal injection.** `Mob.targetSelector` is protected and the species part has no access transformer. Behaviour is driven by `EntityTickEvent.Post` (every 10 ticks, only for mobs that carry our attachment) and `LivingChangeTargetEvent` (cancel or replace a retarget). Public API only: `Mob.setTarget`, `PathNavigation.moveTo`.
5. **Moonblood Surge and Wolf Spirits are granted-only skills** (`SkillSpec.grantedOnly`, `GrantedSkills.RULES`, the S-WOL-8 precedent), not bought ones, so no ladder pays for them and `BalanceInvariantsTest` ("a tree costs 80% to 110% of what its ladder pays") is untouched. Surge is granted to a werewolf in a pack with at least one other member; Wolf Spirits to an Alpha or True Alpha. Ids `S-WOL-9`, `S-WOL-10`.
6. **A recruited NPC is a pack member of the pack its owner is in**, resolved live (`PackIndex.leaderOf(owner)`), never written into `PackIndex` (its members are player UUIDs and every consumer does `SireCall.player(...)`). NPC members live in an entity attachment (`NpcBond`) plus a SavedData `NpcIndex` (for the Pack page while the NPC is unloaded). A lone player is a pack of one, so they can recruit.
7. **The weak spark is its own field**, `WolfState.weakSparks` and `weakProgress`, not part of `sparks`. That makes "counts for nothing", "not stolen" and "lost on a cure" true by construction: `effectiveSparks`, `transferableSparks`, the cap and Deucalion's 3+ never read it.
8. **A weak spark is granted straight to the killer** (no item to drop, dupe or steal), through the same rule as a steal: `PackRules.stealBy` decides TAKES, PROTECTED (destroyed, killer keeps the path) or NEVER (True Alpha). See open question 1.
9. **Rule numbers R140 to R149** are reserved in `SPECIES-RULES.md` for this plan (R110 and R120 to R127 are taken).

## Common to every phase

- **TDD, rule tables first.** Each phase starts with a pure class in `core/` and a JUnit class that has one test per table row (the style of `PackRulesTest`), then glue, then GameTests. Every test is checked to fail with its rule reverted (the mutants habit of plan 18; list the mutants in the PR).
- **UI first.** A task is not done until its hub path exists in all three themes and the lang keys pass `HubLangCoverageTest`; every new config key has an Admin row (`AdminCoverageTest`, `UiReferencesTest` fail otherwise); every new `/pack ...` form has a hub button (`AdminCommandsTest`).
- **Server authority.** Every hub action is a payload the server validates (owner or leader, range, cooldown). The client sends an opaque NPC token (an `NpcIndex` short id), never an entity UUID (IA section 3.7 rule 5).
- **Old saves.** Every new codec field is `lenientOptionalFieldOf` with a default; `NpcIndex` skips a bad entry, not the file (the `PackIndex.load` style).
- **Docs.** Each PR updates `docs/parts/species.md` (and `species_tensura.md` for 15d), `SPECIES-RULES.md` (R140 to R149), `docs/balance.md` (new numbers), `docs/mixins.md` ("species 3 of 3, none added"), the wiki (`Werewolves-And-Packs`, `Configuration`, `Commands`, `Known-Limits`), and the CHANGELOG with the upgrade note.
- **Matrix.** Each PR runs the 10 runs of plan 18: `build test`, the full GameTests, `-PnoWerewolves -PnoCurios`, `-PnoLinkedMods`, and `-PpartsOff` for species, artifacts, speciesTensura, supernatural, supernaturalTensura, hud (`celestials` is one more in CI). GameTests of 15b to 15d are registered only when Werewolves is loaded (15d Tensura ones only with Tensura).
- **Screens.** Hidden safe shots only: `runSafeShots` under `focus-watch.ps1`, never a visible client (`docs/safe-screenshots.md`), three themes at scale 2 and 4, saved in `docs/superpowers/design/npc-packs/`. NEVER run a Minecraft client by hand.
- **No push to main.** Each PR waits for green CI and the review panel.

## Rules text to add to `SPECIES-RULES.md` (drafted here, finalised per phase)

- **R145** An NPC Alpha's killer gets a weak spark: it counts for nothing, cannot be stolen, grows while its holder is online (`weak_spark_grow_days`), becomes a normal spark by the rules of a steal, is lost on a cure; a protected Beta or Omega with an open path destroys it instead, a True Alpha never holds one.
- **R146** Moonblood Surge (a pack buff with a price) and Wolf Spirits (an Alpha's summon) are granted skills.
- **R147** The Alpha Trial gives a spark to a Beta (a second Alpha) or an Omega (a new pack); it warns first when the path to True Alpha is open; a spark ever held closes it for good.
- **R148** A recruited NPC wolf (the Werewolf Brother rite) is a member of its owner's pack with orders Follow, Guard, Rest, hunts and sorts, counts as a part of a Beta for the pack bonus (capped share), is protected as a member, and never takes the spark.
- **R149** With Tensura, a subordinate of a pack member (an NPC member's too) is a member of the same pack, keeps Tensura's orders, and counts less than a Brother.

## Open questions for the owner (answered above)
